# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AgentVerse turns an AI agent's tool-calling workflow into a real-time, side-view JRPG battle: the agent is the hero, the user's task is the boss. Every Grok tool-call/result becomes a skill-cast/hit in the fight. Hackathon project (~12h), see `plan.md` for the full pitch, scope, and current priority queue for remaining work.

## Commands

```
npm run dev          # runs vite (5173) + express API (8787) together; vite proxies /api -> 8787
npm run web           # frontend only
npm run server        # backend only (tsx watch server/index.ts)
npm run build         # tsc -b && vite build  — this IS the typecheck; no separate lint/test script exists
npm run gen:assets    # regenerate default hero/boss/background sprites via Grok Imagine into public/sprites/
node scripts/shoot.mjs [--journey]   # Playwright screenshots to /tmp/av-art/ — use this to visually verify UI changes (dev server must already be running)
```

Requires `XAI_API_KEY` in `.env` (copy from `.env.example`). No test suite — `npm run build` (tsc -b) is the correctness gate; use `scripts/shoot.mjs` for visual verification of battle/UI changes.

## Architecture: the event → battle spine

Everything hangs off one pipeline (see `plan.md` §3 for the full diagram):

```
User task → POST /api/run (server/index.ts)
  → streamText(xai.responses(MODEL), { tools: web_search/x_search/code_execution })
  → fullStream events re-emitted as raw SSE frames
→ src/agent/run.ts (runAgent) reads the SSE stream
→ src/battle/eventMapper.ts (mapEvent) — the ONLY place that decides "what does this agent step mean in the fight"
→ src/battle/store.ts (useBattle, zustand) — applies BattleAction, mutates hero/boss HP, log, round
→ React components (src/components/battle/*) subscribe and animate off `lastAction`
```

`src/battle/types.ts` is the contract for the whole spine (`StreamEvent`, `BattleAction`, `BattleState`) — read it first when touching any part of this pipeline. Changing the shape of an event requires updating the mapper, the store's `apply` reducer, and whatever component reads the new action type.

Key mapper rules to preserve: `text-delta` accumulates into `answer` (the agent's real deliverable, not just battle-log flavor text); a boss reaching 0 HP declares victory immediately on the `hit` action rather than waiting for the trailing `finish` event (avoids a laggy-feeling win); a mid-stream `error` is treated as a scratch (agent takes damage, quest continues), true defeat is only decided when the stream ends with no answer.

## Sprites / asset pipeline

Sprites are 4-pose (`idle/attack/hurt/cast`) transparent PNGs. Both the build-time default generator and the runtime HITL designer share `scripts/spritePipeline.mjs` logic (server-side duplicate lives in `server/design.ts` since it needs to run in the Express process, not a script):

```
Grok Imagine → one sprite sheet (4 poses in a row, solid magenta #C8288C background)
  → Jimp: crop into 4 frames, chroma-key the corner-sampled background color to transparent
  → PNG (files under public/sprites/ for defaults, base64 data URLs for HITL-designed characters)
```

`src/battle/sprites.ts` defines the `Pose`/`CharacterSprites` contract and `poseForAction` (which pose a side shows for a given `BattleAction`). `src/battle/characters.ts` holds the active hero/boss sprite set (defaults from `public/sprites/manifest.json`, overridden by the Design Studio). `src/battle/journey.ts` is a separate side-scrolling "path of foes" model (waypoints along the boss fight, sprites from `public/sprites/foes.json` generated by `scripts/genFoes.mjs`) — don't confuse it with the hero/boss battle sprites.

## Other domains

- **Loadout** (`src/loadout/`): equipping items (backed by `catalog.ts`) computes six ability stats and derives which real backend tools (`web_search`/`x_search`/`code_execution`) the agent is allowed to use via `useLoadout.getState().getEnabledTools()` — this is what `src/agent/run.ts` sends to `/api/run`. Equipping/unequipping gear is not cosmetic; it changes agent capability.
- **Progression** (`src/progression/`): "learn by doing" — `awardQuest` converts which skills were cast this run into XP + stat growth, persisted to `localStorage` (`agentverse:progression`). Growth combines with loadout stats (`combineStats`) for the final displayed stats.
- **Design Studio** (`src/design/`, `server/design.ts`): HITL character/boss creation. `POST /api/design` fans out N parallel "design agent" chat calls (each proposes a distinct art-direction prompt) to Grok Imagine in parallel, returns candidate sheets; `POST /api/design/finalize` slices+keys the chosen one.
